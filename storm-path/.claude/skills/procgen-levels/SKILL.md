# Процедурные уровни

Уровень = последовательность **блоков** (40–80 м) по биому. Блок — параметрический шаблон с ограничениями, а не случайный набор объектов. Опыт прототипа: см. `../index.html` (функции `CH.*`) и навык `level-design` в корневом проекте — там проверенные числа и правила честности.

## Физика (стартовые числа из прототипа)

Крейсер 21 м/с; полный прыжок 14.8 м / высота 2.33; короткий 9.2 м / 1.22; с двойным 24.1 м / 4.27; кувырок 0.55 с, высота хитбокса 0.9; подъём шагом до 0.45 м, «доводка» к краю до 0.65 м. В Unity это константы в `MovementTuning` (ScriptableObject). Изменили движение — пересчитайте таблицу и прогоните массовую проверку.

## Конвейер генерации

```
LevelSpec { seed, biome, k, branch?, length } 
 1. Ритм: грамматика выдаёт последовательность «тактов»: Разгон | Напряжение | Пик | Передышка
 2. Такт → выбор блока из набора биома по тегам и k (веса, запрет повторов подряд)
 3. Параметры блока: из диапазонов, суженных ограничениями (зазоры ≤ дальности прыжка на ожидаемой скорости и т. д.)
 4. Слои поверх трассы: короткие пути веток → кристаллы/сферы → угрозы биома → декор
 5. Быстрая аналитическая проверка (traversal-validation, уровень 1)
 6. Провал → новый подseed для этого блока (до 8 раз) → другой блок → запасной ручной блок
```

Генерация детерминирована: `rng = Rng(seed)`; у каждого блока свой подseed `hash(seed, индекс)`, чтобы перегенерация одного блока не меняла остальные.

## Грамматика ритма

```
Уровень  := Вход Акт+ Финал
Акт      := Разгон Напряжение{1..3} (Пик | Передышка)
Вход     := ровная площадка 30 м + контрольная точка
Финал    := сцена биома (портал, обрыв, арена шторма) 50 м
```

После Пика всегда Передышка или Разгон. Контрольная точка — между каждыми двумя тактами.

## Блок

```csharp
[CreateAssetMenu] public class ChunkDef : ScriptableObject {
  public string id; public BiomeId[] biomes; public Beat beat;     // Разгон/Напряжение/Пик/Передышка
  public Vector2 kRange;                                           // для каких сложностей
  public ChunkParam[] parameters;                                  // имя, диапазон, зависимость от k
  public Constraint[] constraints;                                 // «gap <= jumpReach(expectedSpeed) - 2»
  public BranchSlot[] branchSlots;                                 // где можно вставить короткий путь ветки
  public HazardSlot[] hazardSlots;                                 // где разрешены угрозы биома
  public ChunkBuilder builder;                                     // код, который ставит объекты по параметрам
}
```

Ожидаемая скорость на входе блока считается по предыдущим блокам (ускорители, обрывы) — от неё зависят допустимые зазоры. Если скорость на входе неизвестна точно, берём **нижнюю** оценку (скорость новичка `0.85 V`) для обязательных прыжков и **верхнюю** для проверки «не перелетит ли приземление».

## Слои

1. **Короткие пути веток**: для каждой ветки 1–2 слота на уровень (см. `abilities-progression`): хрупкая стена → ход; лазерный забор → короткий путь; разрыв → верхний маршрут. Выгода считается в секундах и балансируется между ветками.
2. **Кристаллы времени** (Хронопустошь): сначала обязательные на основном пути по расчёту таймера, потом бонусные на рискованных ответвлениях.
3. **Сферы лечения**: 0–2 на уровень, только на ответвлениях.
4. **Угрозы биома**: только в `HazardSlot` блоков; молнии не на узких балках и не в точках приземления; падающие обломки — перед игроком, не над обязательным прыжком.
5. **Искры/осколки** вдоль идеальной линии — подсказка пути.
6. **Декор** вне трассы и не выше 4.5 м над ней.

## Набор блоков на биом (минимум для запуска)

- Общие: прямая, пропасти, стены, балки, ступени, обрыв, батут, ускоритель.
- Пекло: длинный разгон с обломками, «мост рушится за спиной», лавовые разломы.
- Хронопустошь: развилка «короткий путь с кристаллом / длинный безопасный», карусель из движущихся платформ.
- Грозовые пики: широкие плато для уклонения, громоотводы-проводники, узкий гребень без молний (передышка).
