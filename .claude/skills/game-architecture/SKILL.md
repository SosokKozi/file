# Архитектура игры

Прототип живёт в `index.html`: один IIFE со всем кодом. Его механика проверена, поэтому при переносе в модули **поведение не меняем**: те же константы, тот же порядок шагов, то же столкновение. Перенос считается законченным, когда бот из `tools/playtest` проходит все миры с теми же результатами, что и до него.

## Целевая структура

```
src/
  main.ts               точка входа, создаёт Game и запускает цикл
  core/
    loop.ts             фиксированный шаг 120 Гц + интерполяция рендера
    rng.ts              mulberry32; единственный источник случайности в геймплее
    input.ts            клавиатура, тач, геймпад → InputFrame { lat, jump, roll } на каждый тик
    events.ts           маленькая шина событий (land, perfect, bonk, die, checkpoint, finish)
  sim/                  ЧИСТАЯ логика, без three.js и DOM — запускается в Node на сервере
    constants.ts        G, JUMP, DJUMP, CRUISE, MAXSPD, R, H, HROLL, ROLL_DUR, PERFECT_WIN…
    player.ts           состояние и шаг игрока
    collide.ts          AABB-коллизии, подъём на ступень, «доводка» к краю
    world.ts            solids, hazards, pads, sparks, checkpoints — данные уровня
    level-gen.ts        чанки уровня: (seed, k, список чанков) → данные мира
    run.ts              Run: время, падения, искры, сплиты; replay-запись
  render/
    scene.ts            renderer, небо, свет, туман, тема мира
    level-view.ts       меши из данных мира, слияние статики, instancing
    runner-view.ts      модель бегуньи, позы, шарф
    fx.ts               частицы, линии скорости, пыль
    camera.ts
  audio/                см. навык game-audio
  ui/                   меню, HUD, экраны результата, лидерборд (DOM + CSS)
  net/                  см. навык competitive-modes
public/                 манифест PWA, иконки, модели .glb, звуки
tools/playtest/         бот и скриншоты
```

Главная граница: **`sim/` ничего не знает о рендере**. Рендер читает состояние симуляции и рисует его. Без этого невозможны призраки, проверка рекордов на сервере и быстрые тесты.

## Игровой цикл

```ts
const STEP = 1 / 120;
let acc = 0;
function frame(now: number) {
  const dt = Math.min((now - last) / 1000, 0.1); last = now;
  acc += dt;
  while (acc >= STEP) {
    const inp = input.sample();          // одно и то же InputFrame на тик
    replay.record(inp);
    sim.step(STEP, inp);
    acc -= STEP;
  }
  view.render(sim, acc / STEP);          // alpha для интерполяции позиций
  requestAnimationFrame(frame);
}
```

- В прототипе шаг зависит от кадра: `dt` делится на подшаги ≤ 1/120. Для повторов и рекордов переходим на строгий фиксированный шаг и накопитель, как выше.
- Ввод «нажатия» (`jump`, `roll`) превращаем в флаг на ближайший тик, а не на кадр. Иначе на 30 FPS нажатия теряются, а на 144 FPS дублируются.
- Таймер забега = число тиков × STEP. Только так время совпадёт на клиенте и на сервере.
- Пауза и сворачивание вкладки (`visibilitychange`) останавливают накопитель.

## Детерминизм — обязательные правила

1. Никаких `Math.random()`, `Date.now()`, `performance.now()` внутри `sim/`. Случайность только из `rng(seed)`; визуальные эффекты могут использовать что угодно.
2. Порядок обхода объектов фиксирован (массивы, а не `Set`/`Map` с удалениями во время прохода).
3. Время для движущихся объектов (`simT`) — сумма тиков, а не реальное время.
4. Не используйте `Math.sin` от больших чисел для критичных вещей без нужды: результаты между движками совпадают на практике, но проверяйте реплеи на Chrome и Safari.
5. Тест: прогон replay дважды → одинаковый хеш состояния каждые 120 тиков.

## Коллизии (как в прототипе)

Игрок — AABB шириной `2R` и высотой `H` (в кувырке `HROLL`). Порядок проверки для каждого твёрдого тела:

1. Сверху (`vy ≤ 0.5` и ноги на прошлом шаге были не ниже `maxY - tol`): ставим на поверхность. `tol` = 0.45 на земле (подъём на ступень) и 0.08 в воздухе.
2. Снизу (`vy > 0`, голова была ниже `minY`): удар головой, `vy = 0`.
3. Спереди: если до верха < 0.65 и не в кувырке — «доводим» на край (прощаем недопрыг), иначе `bonk()`.
4. Сбоку — выталкиваем по X.

Это прощающее поведение — часть «ощущения» игры. Не ужесточайте его без причины.

## Бюджеты производительности (телефон среднего уровня)

| Ресурс | Бюджет |
|---|---|
| Draw calls | ≤ 150 (статика уровня сливается в 1 меш на материал) |
| Треугольники в кадре | ≤ 300 тыс. |
| Пиксельное соотношение | `min(devicePixelRatio, 2)`; адаптивно снижать до 1.25, если кадр > 20 мс три секунды подряд |
| Текстуры | KTX2/Basis, ≤ 1024², атласы |
| Частицы | один `Points` на ≤ 1000 точек |
| Тени | одна карта 1024² от солнца, область ±25 м вокруг игрока, или «пятно» тени как сейчас |
| Память JS | без аллокаций в цикле: переиспользуемые `Vector3`, пулы |

Профилирование: `renderer.info.render.calls`, `renderer.info.render.triangles`, Chrome Performance с замедлением CPU ×4. Переключатель качества (низкое / среднее / высокое) в настройках.

## Ресурсы

- Модели: `.glb`, сжатие `gltf-transform optimize --compress meshopt --texture-compress ktx2`. Загрузка через `GLTFLoader` + `MeshoptDecoder` + `KTX2Loader`.
- Повторяющиеся объекты (шипы, искры, камни фона) — `InstancedMesh`.
- Загружайте мир по требованию; общий набор (бегунья, интерфейс, базовые звуки) — до меню.

## Сборка и публикация

- `npm create vite@latest` → шаблон `vanilla-ts`; `three` из npm, а не с CDN.
- PWA: `vite-plugin-pwa`, `display: "fullscreen"`, `orientation: "any"`, кеш ассетов мира после первой загрузки, работа без сети (кроме онлайн-режимов).
- Хостинг статики: GitHub Pages, Cloudflare Pages или Netlify. Бэкенд — см. `competitive-modes`.
- Перед релизом: бот проходит все миры, Lighthouse PWA ≥ 90, проверка на iOS Safari (звук после касания, полноэкранный режим, безопасные зоны).

## Порядок переноса прототипа

1. Создать Vite-проект, перенести CSS и разметку меню как есть.
2. Вынести `constants.ts`, `rng.ts`, затем `level-gen.ts` (чанки) — проверить, что `finishD` и число искр каждого мира совпадают с прототипом.
3. Вынести шаг игрока и коллизии в `sim/`, подключить к старому рендеру.
4. Перейти на фиксированный шаг; прогнать бота.
5. Разнести рендер, звук и интерфейс.
6. Добавить запись реплеев (нужна для `competitive-modes`).
