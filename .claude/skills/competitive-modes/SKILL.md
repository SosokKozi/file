# Соревновательные режимы

Вся система держится на одном: **детерминированный реплей**. Забег = `{ версия игры, мир, seed, массив ввода по тикам }`. Из него можно восстановить точное время, показать призрака и проверить рекорд на сервере. Сначала сделайте реплеи (см. `game-architecture`), потом всё остальное.

## Формат реплея

```ts
type InputFrame = { lat: -1 | 0 | 1; jump: boolean; roll: boolean };  // на тик 1/120 с

interface Replay {
  v: 1;                 // версия формата
  build: string;        // хеш симуляции (sim/*), а не всего клиента
  world: string;        // "w1".."w5" или "daily-2026-10-05"
  seed: number;
  ticks: number;        // длина забега в тиках = время × 120
  input: Uint8Array;    // RLE: [кол-во тиков, байт состояния] …
  splits: number[];     // тик прохождения каждой контрольной точки
}
```

Байт состояния: биты `left, right, jump, roll`. RLE сжимает минутный забег (7200 тиков) до 1–3 КБ; затем `gzip`/`CompressionStream`.

## Соревнование с собой

1. **Личный рекорд** по каждому миру: время, медаль, сплиты, реплей (`IndexedDB`, локально всегда, на сервер — если вошёл в аккаунт).
2. **Сплиты**: на каждой контрольной точке разница с рекордом («−0.42» / «+1.10»). Это главный крючок для «ещё раз».
3. **Призрак рекорда**: полупрозрачная бегунья проигрывает реплей лучшего забега параллельно. Его позиция берётся из симуляции копии игрока по тикам (стоит ~0.1 мс на тик; можно заранее просчитать траекторию и хранить позиции).
4. **Медали** S/A/B на мир (см. `level-design`) + **испытания** мира: «без падений», «все искры», «5 идеальных подряд», «финиш быстрее 1.5 × эталона без ускорителей». Каждое даёт отметку на карточке мира.
5. **Ежедневная серия**: сыграл ежедневный заезд N дней подряд → награда (скин, рамка ника).
6. **Мастерство**: суммарное время лучших забегов всех миров — единый показатель прогресса.

## Соревнование с другими

| Режим | Как работает | Что нужно |
|---|---|---|
| **Рейтинг мира** | лучшее проверенное время каждого игрока; топ-100 + своё место | сервер, проверка реплея |
| **Рейтинг друзей** | тот же рейтинг, отфильтрованный по друзьям (по коду приглашения) | таблица друзей |
| **Неделя** | рейтинг сбрасывается в понедельник 00:00 UTC, награды топ-1/10/100 | cron |
| **Ежедневный заезд** | мир из `seed = hash(дата)`; у всех один и тот же; одна «зачётная» попытка + неограниченные тренировки, или лучшее за день | генератор `level-gen` |
| **Гонка с призраком** | выбираешь строку в рейтинге → бежишь против её реплея | скачивание реплея |
| **Асинхронный вызов** | отправил ссылку `…/#c-ABC123` другу → он бежит против твоего призрака, ты получаешь результат | короткие коды |
| **Турнир** | мир на 3 дня, в зачёт лучшее время; лиги по уровню | расписание |
| **Онлайн-гонка** | 2–8 игроков стартуют одновременно, видят друг друга | WebSocket-комната |

Порядок внедрения (каждый шаг — играбельный результат):
1. Локальные рекорды, сплиты, призрак рекорда.
2. Ежедневный заезд (локально).
3. Аккаунт + рейтинги миров и ежедневного заезда + призраки из рейтинга.
4. Друзья и вызовы по ссылке.
5. Недели и турниры.
6. Онлайн-гонки.

## Онлайн-гонки в реальном времени

Не нужно «честное» серверное моделирование физики каждого игрока: в раннере игроки не сталкиваются. Схема:

- Комната на сервере (Durable Object / процесс Node с `ws`). Хост задаёт мир и seed, сервер рассылает `start_at` (время старта через 3 с, синхронизация часов по пингу).
- Каждый клиент симулирует **только себя** и 10 раз в секунду отправляет `{ tick, x, y, z, state }`. Соперники отображаются интерполяцией с задержкой 100–150 мс.
- На финише клиент отправляет полный реплей; место определяет сервер **по проверенному реплею**, а не по сообщениям.
- Отключился — бежит дальше как призрак по последним данным; не финишировал за 2 × эталон — DNF.

## Античит

1. Сервер принимает только реплей, а не «время». Время = `ticks / 120` **после** прогона реплея в той же `sim/` (Node). Не совпало, не дошло до финиша, или `build` неизвестен → отклонить.
2. Проверка лёгкая: минутный забег — 7200 шагов, < 50 мс CPU. Проверяйте асинхронно (очередь), показывайте «Проверяется…».
3. Ограничения: не больше N отправок в минуту на игрока; реплей ≤ 64 КБ.
4. Подозрительные (время < 0.6 × эталон или нечеловеческий ввод: > 30 смен направления в секунду) помечаются для ручной проверки, а не банятся автоматически.
5. Версии: при изменении `sim/` меняется `build`, старые рекорды остаются в архивном рейтинге своей версии или пересчитываются.
6. Клиенту доверять нельзя ни в чём, кроме ввода.

## Бэкенд

Два готовых варианта (подробная схема — в `references/backend.md`):

- **Supabase** (Postgres + Auth + Edge Functions + Storage + Realtime): быстрее всего начать; Edge Function проверяет реплей, реплеи лежат в Storage, комнаты гонок — через Realtime-каналы (для 2–8 игроков достаточно).
- **Cloudflare** (Workers + D1 + R2 + Durable Objects): дешевле при росте, Durable Object — естественная «комната» гонки и место для проверки реплея.

Аккаунты: анонимный вход сразу (игрок не должен регистрироваться, чтобы попасть в рейтинг), позже привязка Google / Apple / почты, чтобы не потерять прогресс.

## Ники и безопасность игроков

- Ник 3–16 символов, буквы/цифры/`_`, фильтр мата (русский + английский), уникальность без учёта регистра.
- Никакого свободного чата в первой версии: только реакции-эмодзи после гонки. Это снимает модерацию и защищает детей.
- Возможность скрыть себя из публичного рейтинга; удаление аккаунта и данных по запросу. Персональные данные — минимум (ник, хеш входа).

## Что показывать игроку

- После финиша: «Новый рекорд!», место в мире и среди друзей, «до следующей медали 0.8 с», кнопка «Бежать против №N выше тебя».
- В меню: ежедневный заезд с таймером до сброса и числом участников.
- Уведомление (если разрешено): «Тебя обогнали в рейтинге мира 3».
