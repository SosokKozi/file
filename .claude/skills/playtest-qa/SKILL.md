# Плейтест и проверка качества

Инструменты лежат в `tools/playtest/` (см. `tools/playtest/README.md`). Они открывают `index.html` в Chromium через Playwright и управляют игрой через тестовый хук `window.__game`:

| Хук | Что делает |
|---|---|
| `startLevel(i)` | запустить мир `i` (с нуля) |
| `simFrame(dt)` | один шаг логики без рендера — бот гоняет мир за секунды |
| `P`, `RUN`, `LV`, `keys`, `press(a)` | состояние игрока, забега, мира; нажатия |
| `pose(поля, кадров, режим)` | поставить бегунью в позу и отрендерить кадр крупным планом |

При переносе в модули (`game-architecture`) сохраните этот хук, иначе инструменты сломаются.

## Обязательный прогон после изменений

```sh
cd tools/playtest
npm install            # один раз
node bot.js            # все миры; код выхода 1, если бот не дошёл или есть ошибки страницы
```

Как читать результат (по строке на мир):
- `done: false` и `reachedM` → бот застрял или погиб много раз на этом метре. Найдите чанк в `chunks` (`имя@метр начала`) и снимите скриншот.
- `deathsAtM` с повторяющимся числом → одно место убивает постоянно. Бот простой (не предсказывает лазеры и балки), поэтому одиночные смерти на лазерах и вращающихся балках нормальны. Серия смертей в одном месте — почти всегда нечестное расстояние: сверьте с правилами в `level-design`.
- `ratio` = время / эталон. Бот бегает близко к идеалу; если `ratio < 0.75`, эталон слишком мягкий, если бот не укладывается в 1.0 без смертей — проверьте, достижимо ли золото человеком.

## Скриншоты

```sh
node shots.js '[[0,160],[2,110]]'   # [мир с нуля, метр] → tools/playtest/shots/world1_160m.png …
```

Посмотрите каждый кадр: читается ли препятствие издалека, не сливается ли бегунья с фоном, не перекрыт ли путь декором, читаемы ли тексты HUD на светлой земле.

## Таблица прыжков

`node physics.js` — дальность и высота прыжков для скоростей 21/30/40/48. Изменили константы в игре — обновите их в `physics.js` и таблицу в `level-design/SKILL.md`.

## Производительность

- В браузере: `renderer.info.render.calls` и `.triangles` (через консоль или временный оверлей). Бюджеты — в `game-architecture`.
- Chrome DevTools → Performance → CPU ×4: кадр ≤ 16 мс в самом нагруженном месте (мир 5, лазеры и частицы).
- Headless Chromium в контейнере рендерит программно и медленно: FPS там не показатель, мерить только на реальном устройстве.

## Детерминизм (когда появятся реплеи)

Прогоните один реплей дважды и сравните хеш состояния каждые 120 тиков; затем тот же реплей в Node (серверная проверка). Любое расхождение — блокер для рейтингов.

## Ручной чек-лист перед публикацией

- [ ] Клавиатура: прыжок, двойной с сальто, боковое сальто (A/D + двойной), кувырок, пике, идеальное приземление.
- [ ] Телефон (iOS Safari и Android Chrome): кнопки, звук после первого касания, полный экран, вырезы экрана, поворот.
- [ ] 60 FPS на телефоне среднего уровня в мирах 1 и 5.
- [ ] Пауза при сворачивании вкладки; продолжение без скачка времени.
- [ ] Рекорды и открытые миры сохраняются после перезагрузки.
- [ ] Нет ошибок в консоли.
- [ ] Онлайн-режимы: потеря сети во время забега не ломает игру, рекорд уходит при восстановлении.
